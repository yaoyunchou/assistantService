# 飞书聊天机器人配置说明

## 概述

当前应用已支持**单向发消息**（如登录提醒、自定义消息）。若要实现**可聊天**（用户发消息给机器人、机器人回复），需要：

1. 在飞书开放平台开启**事件订阅**，订阅「接收消息」事件。
2. 配置一个**公网可访问的 URL**，供飞书把用户消息推送到你的服务。
3. 本应用已提供事件回调接口与回复逻辑，按下面步骤配置即可。

---

## 一、飞书开放平台配置

### 1. 应用与权限

- 使用现有飞书应用（与发消息同一应用即可）。
- 在 **权限管理** 中确保已开通：
  - **接收消息**（`im:message:receive_v1` 等，按控制台实际名称勾选）
  - **发送消息**（已有）
  - **获取用户信息**（若需要根据发送者做逻辑）

### 2. 事件订阅

1. 打开 [飞书开放平台](https://open.feishu.cn/) → 你的应用 → **事件订阅**。
2. **请求地址** 填写（需公网可访问）：
   ```text
   https://你的公网域名/api/feishu/event
   ```
   例如：`https://xxx.ngrok.io/api/feishu/event` 或 `https://your-server.com/api/feishu/event`。
3. 点击 **保存** 或 **验证**：
   - 飞书会向该 URL 发送一次带 `challenge` 的 POST 请求。
   - 本应用会原样返回 `{"challenge": "飞书发来的值"}`，通过校验后即可保存。
4. 在 **订阅事件** 中勾选并添加：
   - **接收消息**（`im.message.receive_v1`）。
5. 发布版本 / 启用后，用户在单聊或群聊中 @ 你的应用机器人 或 给机器人发消息时，飞书会把事件 POST 到上述地址。

---

## 二、公网地址（本机开发时）

本机运行的服务（如 `http://127.0.0.1:5000`）飞书无法访问，需要暴露为公网 URL：

- **ngrok**（示例）：
  ```bash
  ngrok http 5000
  ```
  使用生成的 `https://xxx.ngrok.io`，请求地址填：`https://xxx.ngrok.io/api/feishu/event`。
- **内网穿透 / 云服务器**：将域名或 IP 指到运行本应用的机器，请求地址填：`https://你的域名/api/feishu/event`。

确保 HTTPS（飞书要求），若用 HTTP 仅用于自测，部分功能可能受限。

---

## 三、本应用已实现的能力

| 能力           | 说明 |
|----------------|------|
| URL 校验       | 飞书发来 `challenge` 时，自动返回 `{"challenge": ...}`，通过事件订阅校验。 |
| 接收消息事件   | 处理 `schema 2.0`、`event_type = im.message.receive_v1` 的推送。 |
| 快速响应       | 收到事件后先返回 HTTP 200，再在后台线程里处理并回复，避免飞书 3 秒超时重试。 |
| 回复消息       | 使用飞书「回复消息」接口，在用户发的那条消息所在会话中回复。 |

---

## 四、回复逻辑与自定义

当前默认行为：**把用户发的文本原样回显**（前 200 字 + 前缀「收到：」）。无文本时回复「收到一条消息。」

如需改成你自己的业务（例如查订单、调 AI、关键词回复等）：

1. 打开 **`src/api/routes/feishu_routes.py`**，找到 **`_handle_feishu_message_event`**。
2. 其中已解析：
   - `message_id`：用户消息 ID，用于回复。
   - `user_text`：用户消息文本（来自 `event.message.content` 的 JSON）。
3. 根据 `user_text` 或 `event.sender` 写你的逻辑，得到要回复的 `reply_text`。
4. 调用 **`client.reply_to_message(message_id, reply_text)`** 发送回复。

示例（仅作结构参考）：

```python
# 在 _handle_feishu_message_event 内
if user_text == "帮助":
    reply_text = "可用指令：帮助、订单、状态"
elif user_text.startswith("订单"):
    reply_text = "正在查询订单..."  # 可调用你现有订单接口
else:
    reply_text = f"收到：{user_text[:200]}"
client.reply_to_message(message_id, reply_text)
```

## 五、环境与运行

- 飞书应用凭证仍使用现有 **`.env`**：`FEISHU_APP_ID`、`FEISHU_APP_SECRET`（发消息已用）。
- 事件订阅**不需要**在 `.env` 里新增配置；请求地址在飞书控制台填写即可。
- 若开启飞书「事件加密」，需在应用内解密后再解析 `event`，当前默认按未加密实现。

---

## 六、测试步骤

1. 保存事件订阅并确保请求地址可访问（可用 Postman 或 curl 对 `POST /api/feishu/event` 带 `{"challenge":"test"}` 测返回 `{"challenge":"test"}`）。
2. 在飞书里找到你的应用机器人（单聊或拉进群后 @ 机器人）。
3. 发送任意文字，应收到机器人回复（默认为「收到：xxx」或「收到一条消息。」）。
4. 查看本应用日志，确认无报错；若有 4xx/5xx 或未返回 200，飞书会按策略重试推送。

按以上配置后，应用即可支持「用户发消息 → 服务处理 → 机器人回复」的聊天能力；后续只需在 `_handle_feishu_message_event` 中扩展业务逻辑即可。
