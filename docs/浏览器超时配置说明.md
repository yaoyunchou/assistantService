# 浏览器超时配置说明

## 概述

所有浏览器操作都支持超时控制，默认最长调用时间为 **60秒（1分钟）**。超时后会自动记录日志并释放浏览器资源，确保下一个方法可以正常调用。

## 默认超时时间

| 方法 | 默认超时 | 说明 |
|------|---------|------|
| `get_page()` | 60秒 | 浏览器池获取页面 |
| `execute_with_client()` | 60秒 | 拼多多工具执行操作 |
| `query_with_retry()` | 60秒 | 快递查询（带重试） |

## 使用方式

### 1. 使用默认超时（60秒）

```python
# 方式1：直接使用浏览器池
with browser_pool.get_page() as page:
    page.goto('https://example.com')
    # 超过60秒会自动超时

# 方式2：使用拼多多工具
tool.execute_with_client(callback)
# 超过60秒会自动超时

# 方式3：快递查询
result = query_with_retry(waybill_number, browser_pool)
# 超过60秒会自动超时
```

### 2. 自定义超时时间

```python
# 方式1：浏览器池 - 设置30秒超时
with browser_pool.get_page(timeout=30) as page:
    page.goto('https://example.com')

# 方式2：拼多多工具 - 设置90秒超时
tool.execute_with_client(callback, timeout=90)

# 方式3：快递查询 - 设置45秒超时
result = query_with_retry(waybill_number, browser_pool, timeout=45)

# 方式4：禁用超时（不推荐）
with browser_pool.get_page(timeout=0) as page:
    # 永不超时，可能导致资源占用
    pass
```

## 超时处理流程

```
开始调用
    ↓
启动超时定时器（默认60秒）
    ↓
执行浏览器操作
    ↓
┌──────────────┐
│ 是否超时？    │
└──────┬───────┘
       ├─→ 是：记录超时日志 → 抛出 BrowserTimeoutError
       └─→ 否：正常完成 → 返回结果
              ↓
        finally: 释放浏览器
              ↓
        标记为空闲，供下一个请求使用
```

## 异常处理

```python
from spider.query_manager import BrowserTimeoutError

try:
    with browser_pool.get_page(timeout=30) as page:
        page.goto('https://slow-website.com')
        # ... 执行操作
except BrowserTimeoutError as e:
    print(f"操作超时: {e}")
    # 浏览器已自动释放，可以继续下一个操作
except Exception as e:
    print(f"其他错误: {e}")
```

## 超时时间建议

根据不同的操作类型，建议设置不同的超时时间：

| 操作类型 | 推荐超时 | 说明 |
|---------|---------|------|
| 快速查询 | 15-30秒 | 简单的数据查询 |
| 页面加载 | 30-60秒 | 普通页面加载 |
| 复杂操作 | 60-120秒 | 需要多步操作的自动化 |
| 批量处理 | 120-300秒 | 批量数据处理 |

### 注意事项

1. **不要设置过短的超时时间**
   - 网络不稳定时可能导致频繁超时
   - 建议至少设置15秒以上

2. **不要设置过长的超时时间**
   - 页面卡住时会长时间占用资源
   - 建议不超过300秒（5分钟）

3. **根据实际情况调整**
   - 本地开发环境：可以设置较短的超时
   - 生产环境：建议设置较长的超时，考虑网络波动
   - 国际网站：建议增加超时时间

## 常见问题

### Q1: 为什么我的操作总是超时？

**A:** 可能的原因：
- 超时时间设置太短
- 网络速度慢
- 目标网站响应慢
- 页面加载资源过多

**解决方案：** 增加超时时间，如从60秒改为90秒或120秒

### Q2: 超时后浏览器会自动释放吗？

**A:** 是的！超时后浏览器会立即被标记为空闲，并可以被下一个请求使用。这是通过 `finally` 块保证的。

### Q3: 超时会影响其他正在运行的操作吗？

**A:** 不会。每个浏览器实例是独立的，一个实例超时不会影响其他实例。

### Q4: 可以禁用超时吗？

**A:** 可以，设置 `timeout=0` 即可禁用超时。但不推荐，因为可能导致资源无法释放。

### Q5: 超时后数据会丢失吗？

**A:** 是的，超时会中断当前操作，未完成的操作会被放弃。建议捕获 `BrowserTimeoutError` 异常进行重试或其他处理。

## 最佳实践

```python
from spider.query_manager import BrowserPool, BrowserTimeoutError
import time

# 1. 创建浏览器池
pool = BrowserPool(headless=True)

# 2. 使用重试机制处理超时
max_retries = 3
for attempt in range(max_retries):
    try:
        with pool.get_page(timeout=60) as page:
            page.goto('https://example.com')
            # 执行操作
            break  # 成功则跳出循环
    except BrowserTimeoutError:
        if attempt < max_retries - 1:
            print(f"超时，重试中... ({attempt + 1}/{max_retries})")
            time.sleep(2)  # 等待2秒后重试
        else:
            print("多次超时，放弃操作")
            raise

# 3. 根据操作类型设置不同的超时
def quick_check(url):
    """快速检查 - 15秒超时"""
    with pool.get_page(timeout=15) as page:
        page.goto(url)
        return page.title()

def full_scrape(url):
    """完整抓取 - 120秒超时"""
    with pool.get_page(timeout=120) as page:
        page.goto(url)
        # 执行复杂操作
        return page.content()
```

## 技术细节

### 超时实现原理

1. 使用 `threading.Timer` 创建定时器
2. 定时器在指定时间后触发回调函数
3. 回调函数设置超时标志 `is_timeout = True`
4. 上下文管理器退出时检查超时标志
5. 如果超时，抛出 `BrowserTimeoutError` 异常
6. `finally` 块保证浏览器资源一定会被释放

### 线程安全

- 每个浏览器实例有独立的超时定时器
- 定时器在守护线程中运行，不会阻塞主线程
- 使用锁保护实例状态的修改
- 确保并发安全
