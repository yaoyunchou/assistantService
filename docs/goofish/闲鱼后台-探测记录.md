## 1. 站点结构（已验证）

闲鱼卖家工作台是 **ICE（Alibaba React 框架）单页应用**，shell 与业务页分离：

| 项 | 值 | 置信度 |
|----|-----|--------|
| 入口 | `https://seller.goofish.com/?site=COMMONPRO#/seller-item/publish` | 已验证 |
| 页面标题（已登录 shell） | `闲鱼卖家工作台` | 已验证 |
| 静态资源根 | `https://g.alicdn.com/idle-pc/seller-workbench/0.1.56/` | 已验证 |
| App 挂载点 | `#ice-container`、`#J_AppMain` | 已验证 |

### shell 路由清单（从 `js/main.js` 提取，已验证）

```
login, iframe, im, im-desktop, account-check,
no-permission, notification-center, playground,
select-site, /download, *
```

**关键结论**：shell 路由里**没有** `seller-item/publish`。存在 `iframe` 路由与对应的 `p_iframe-index.js`（仅 522 字节，thin wrapper）。

这说明 **业务页（发布 / 商品列表）是 iframe 承载的**，真实 iframe URL 由登录后的菜单接口 `mtop.alibaba.idle.seller.platform.sys.menu.query` 下发。

### 对实现的直接影响

- Playwright **不能**在主 frame 上 `page.evaluate` 找发布表单，必须用 `frame_locator` / `page.frames` 进入 iframe
- 主 frame 的 `document.body.innerText` 在登录页实测为**空**（长度 0），因为内容都在 iframe 里 —— 任何基于 body 文本的判定都会失效

## 2. 登录态判定（已验证，且优于原计划方案）

### 未登录时的行为（已验证）

访问 `#/seller-item/publish` 未登录 → **自动重定向**到：

```
https://seller.goofish.com/#/login?redirectUrl=<urlencoded 原地址>
```

| 信号 | 值 | 置信度 |
|------|-----|--------|
| URL 特征 | 含 `#/login` | 已验证 |
| 页面标题 | `登录 - 闲鱼卖家工作台` | 已验证 |
| 登录容器 | `#xy-login-iframe`、`#alibaba-login-box`（iframe） | 已验证 |
| 登录 iframe src | `https://passport.goofish.com/mini_login.htm?lang=zh_cn&appName=xianyu&appEntrance=seller_web&styleType=vertical...` | 已验证 |

### 推荐判定方式：mtop 探针（已验证）

`lib-mtop@2.7.3` 全局可用，`window.lib.mtop.request` 可直接调用。实测未登录时：

```js
await window.lib.mtop.request({
  api: 'mtop.alibaba.idle.seller.platform.query.login.merchant.info',
  v: '1.0', data: {}
})
// 未登录 → reject，ret = ["FAIL_SYS_SESSION_EXPIRED::Session过期"]
```

**这是最可靠的登录判定**，原因：

1. 不依赖 URL（SPA hash 路由跳转不触发 navigation）
2. 不依赖 DOM（class 名带构建哈希，见第 3 节）
3. 不依赖 iframe 是否加载完成
4. 登录成功时顺带返回商户信息（可用于回填「上架店铺」）

判定规则：`ret` 含 `FAIL_SYS_SESSION_EXPIRED` 或 `FAIL_SYS_TOKEN` → 未登录；`ret` 含 `SUCCESS` → 已登录。

## 3. 选择器风险：CSS Modules 构建哈希（已验证）

登录页实测 class 名：

```
loginPage--ScuLfa2N
loginContainer--T37Gfdvt
loginIframeWrap--JMG09xhG
```

`--XXXXXXXX` 后缀是 CSS Modules 构建哈希，**每次前端发版都会变**。

**硬性约束**：代码中禁止使用带 `--` 哈希后缀的 class 选择器。只允许：

1. 稳定 ID：`#ice-container`、`#J_AppMain`、`#xy-login-iframe`
2. 语义属性：`[data-*]`、`role=`、`name=`、`type=`
3. 文本匹配：`get_by_text('立即发布')` 等
4. 结构相对定位（配合上述锚点）

## 6. 运行时探测方案（Phase 1 交付的自助工具）

由于上述接口只在登录态可见，模块内置**探测器**，把 Phase 0 的未知项转成一键自助采集：

**入口**：`POST /api/goofish/probe`

**机制**（`src/spider/goofish/api_probe.py`）：

1. 过登录门禁
2. 在主 frame 与所有子 frame 注入 hook，包裹 `window.lib.mtop.request`，并监听 `page.on('response')`
3. 打开目标页（发布页 / 商品列表页），可选自动滚动与翻页
4. 记录每次 mtop 调用的 `api`、`v`、请求参数、响应结构骨架（只记结构与少量样本值，不落敏感数据）
5. 输出到 `logs/goofish-pw/probe/<时间戳>/`：
   - `apis.json` — API 清单与参数
   - `sample-<api>.json` — 响应样本（供做 fixture）
   - `frames.json` — iframe URL 清单
   - `screenshot.png`

**用法**：登录后在闲鱼页面点一次「探测接口」，把 `apis.json` 里的商品列表 API 名填进 `config.py` 的 `ITEM_LIST_API`，Phase 2 即可切到 mtop 直调。

## 7. 已确认的架构结论

| 结论 | 依据 |
|------|------|
| 数据获取优先 **`lib.mtop.request` 直调**，而非 XHR 拦截或 DOM 抓取 | `lib.mtop` 全局可用且实测可调；直调可控分页、无需点 UI |
| 登录判定用 **mtop 探针**，URL/DOM 仅作辅助 | 实测 `FAIL_SYS_SESSION_EXPIRED` 稳定可辨 |
| DOM 操作必须 **frame-aware** | shell 只有 `iframe` 路由，业务页在 iframe 内 |
| 禁用哈希 class 选择器 | 实测 class 带 `--ScuLfa2N` 式构建哈希 |
| API 名与选择器必须**集中配置 + 可运行时探测** | 关键接口登录后才可见 |
