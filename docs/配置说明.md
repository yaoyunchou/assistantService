## 1. 系统托盘配置（右下角任务栏）

### 1.1 配置文件位置

**文件**: `src/config.py`

```python
class Config:
    # 系统托盘配置
    TRAY_ENABLED = True  # 是否启用系统托盘
    TRAY_ICON_PATH = None  # 托盘图标路径，None则使用默认图标
```

### 1.2 配置项说明

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `TRAY_ENABLED` | bool | `True` | 是否启用系统托盘功能。`True`=启用，`False`=禁用 |
| `TRAY_ICON_PATH` | str/None | `None` | 托盘图标文件路径。`None`=使用默认生成的图标，字符串=使用指定路径的图标文件（PNG或ICO格式） |

### 1.3 实现位置

**代码文件**: `src/tray/tray_icon.py`

**关键类**: `TrayIcon`

**主要方法**:
- `start()`: 启动托盘图标
- `stop()`: 停止托盘图标
- `_create_menu()`: 创建右键菜单
- `_load_icon_from_file()`: 加载图标文件

### 1.4 图标文件位置

**开发环境**:
- `src/static/images/icon.png`
- `src/static/images/icon.ico`

**打包环境**:
- `dist/main/static/images/icon.png`
- `dist/main/static/images/icon.ico`

**加载顺序**:
1. 优先从文件加载图标
2. 如果文件不存在，使用PIL动态生成默认图标

### 1.5 托盘菜单配置

**位置**: `src/tray/tray_icon.py` 的 `_create_menu()` 方法

**默认菜单项**:
- 打开界面
- 退出

**自定义菜单示例**:
```python
items = [
    pystray.MenuItem('打开界面', self._on_open_clicked),
    pystray.MenuItem('设置', self._on_settings_clicked),
    pystray.MenuItem('关于', self._on_about_clicked),
    pystray.Menu.SEPARATOR,  # 分隔线
    pystray.MenuItem('退出', self._on_quit_clicked),
]
```

### 1.6 打包配置中的相关设置

**文件**: `main.spec`

在 `hiddenimports` 中需要包含：
```python
hiddenimports=[
    'pystray',              # 系统托盘库
    'PIL',                  # 图像处理库
    'PIL._tkinter_finder',
    'pystray._win32',       # Windows平台特定模块
    # ...
]
```

### 1.7 常见问题

#### Q1: 托盘图标不显示

**可能原因**:
- pystray或Pillow未正确安装
- 系统托盘区域被隐藏
- 图标文件路径错误

**解决方法**:
1. 检查依赖：`pip list | findstr pystray`
2. 检查系统托盘区域设置（Windows设置 > 个性化 > 任务栏）
3. 查看控制台错误信息
4. 尝试禁用托盘功能测试：`TRAY_ENABLED = False`

#### Q2: 托盘菜单无响应

**可能原因**:
- 回调函数未正确设置
- 线程问题

**解决方法**:
1. 检查 `src/main.py` 中的回调函数是否正确传递
2. 确保在主线程中处理UI操作

**相关文档**: 详细说明请参考 [开发指南.md](开发指南.md#6-系统托盘配置)

## 2. 开机自启动配置

### 2.1 实现位置

**代码文件**: `src/utils/startup.py`

**关键函数**:
- `is_startup_enabled()`: 检查是否已添加到开机启动
- `add_to_startup()`: 添加到开机启动
- `remove_from_startup()`: 从开机启动中移除
- `get_exe_path()`: 获取exe文件路径

### 2.2 注册表位置

**注册表路径**:
```
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
```

**键名**: `JNSpider`

**值**: `"C:\path\to\main.exe"` (带引号的完整路径)

### 2.3 自动添加逻辑

**位置**: `src/main.py` 的 `main()` 函数

**代码**:
```python
# 检查并添加到开机启动（如果还没有）
if not is_startup_enabled():
    print("[Main] 检测到未设置开机自启动，正在自动添加...")
    add_to_startup()
else:
    print("[Main] 开机自启动已启用")
```

**行为**:
- 首次运行自动添加到启动项
- 如果已存在，不重复添加

### 2.4 路径获取逻辑

**开发环境 vs 打包环境**:

```python
def get_exe_path():
    if getattr(sys, 'frozen', False):
        # 打包后的exe环境
        return sys.executable  # 返回exe完整路径
    else:
        # 开发环境
        jnspider_path = Path(__file__).parent.parent / 'JNSpider.py'
        return str(jnspider_path.absolute())
```

**说明**:
- `sys.frozen`: PyInstaller打包后设置的属性
- 开发环境返回Python脚本路径
- 打包环境返回exe路径

### 2.5 API管理接口

**位置**: `src/api/routes/`（开机自启接口在 `health.py`）

**接口**: `/startup`

**方法**:
- `GET`: 查询自启动状态
- `POST`: 启用自启动
- `DELETE`: 禁用自启动

**使用示例**:
```bash
# 查询状态
curl http://127.0.0.1:8099/startup

# 启用自启动
curl -X POST http://127.0.0.1:8099/startup

# 禁用自启动
curl -X DELETE http://127.0.0.1:8099/startup
```

### 2.6 注册表操作详解

**使用的Windows API**: `winreg` 模块

**关键操作**:
```python
import winreg

# 打开注册表键
key = winreg.OpenKey(
    winreg.HKEY_CURRENT_USER,
    STARTUP_REG_KEY,
    0,
    winreg.KEY_WRITE
)

# 写入值（路径用引号包裹，处理空格）
exe_path_quoted = f'"{exe_path}"'
winreg.SetValueEx(key, STARTUP_APP_NAME, 0, winreg.REG_SZ, exe_path_quoted)

# 读取值
value, _ = winreg.QueryValueEx(key, STARTUP_APP_NAME)

# 删除值
winreg.DeleteValue(key, STARTUP_APP_NAME)
```

### 2.7 常见问题

#### Q1: 开机自启动不生效

**可能原因**:
- 注册表写入失败
- exe路径错误
- 杀毒软件拦截

**解决方法**:
1. 使用注册表编辑器查看：`regedit`，导航到 `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`
2. 检查键名 `JNSpider` 是否存在，值是否正确
3. 检查杀毒软件设置，添加白名单
4. 查看控制台错误信息

#### Q2: 路径包含空格导致启动失败

**解决方法**:
- 代码中已使用引号包裹路径：`f'"{exe_path}"'`
- 确保 `get_exe_path()` 返回正确路径

#### Q3: 开发环境自启动问题

**说明**:
- 开发环境会使用Python脚本路径
- 需要确保Python环境正确配置
- 建议只在打包后的exe中使用自启动功能

**相关文档**: 详细说明请参考 [开发指南.md](开发指南.md#7-开机自启动配置)

## 3. 打包配置详解

### 3.1 打包配置文件

**文件**: `main.spec`

**用途**: PyInstaller打包配置文件，定义如何将Python应用打包为exe

### 3.2 配置结构

```python
# 1. 路径配置
project_root = Path(SPECPATH)  # spec文件所在目录
src_dir = project_root / 'src'  # 源代码目录

# 2. Analysis - 分析阶段（收集依赖）
a = Analysis(...)

# 3. PYZ - Python字节码打包
pyz = PYZ(a.pure)

# 4. EXE - 可执行文件配置
exe = EXE(...)

# 5. COLLECT - 收集所有文件（onedir模式）
coll = COLLECT(...)
```

### 3.3 Analysis 配置详解

**作用**: 分析Python代码，收集所有依赖

**关键配置项**:

| 配置项 | 说明 | 示例 |
|--------|------|------|
| `scripts` | 主程序入口文件列表 | `[str(src_dir / 'main.py')]` |
| `pathex` | Python模块搜索路径 | `[str(src_dir)]` |
| `binaries` | 二进制文件列表（如DLL） | `[]` |
| `datas` | 数据文件列表（模板、静态资源等） | `[(源路径, 目标路径), ...]` |
| `hiddenimports` | 隐藏导入的模块（PyInstaller无法自动检测的） | `['pystray', 'PIL', ...]` |
| `excludes` | 排除的模块（减小体积） | `[]` |
| `noarchive` | 是否不打包为归档文件 | `False` |
| `optimize` | Python优化级别 | `0`（不优化） |

**datas 配置说明**:
```python
datas=[
    (str(src_dir / 'web' / 'templates'), 'web/templates'),
    (str(src_dir / 'static'), 'static'),
]
```
- 格式：`(源路径, 目标相对路径)`
- **PyInstaller 6 onedir 模式**下，文件会复制到 `dist/<应用名>/_internal/<目标路径>/`（不是 exe 同目录）
- 代码中读取这些内嵌资源应使用 `get_bundled_data_root()`（返回 `_internal/`），而非 `get_project_root()`（返回 exe 目录）

**hiddenimports 配置说明**:
```python
hiddenimports=[
    'pystray',              # 系统托盘库
    'PIL',                  # 图像处理库
    'pystray._win32',       # Windows平台特定模块
    'flask',                # Flask框架
    'playwright',           # 浏览器自动化
    # ... 其他模块
]
```
- 用于解决PyInstaller无法自动检测的模块
- 特别是平台特定的模块（如`pystray._win32`）

### 3.4 EXE 配置详解

**作用**: 配置可执行文件的生成方式

**关键配置项**:

| 配置项 | 说明 | 当前值 | 说明 |
|--------|------|--------|------|
| `console` | 是否显示控制台窗口 | `True` | `True`=显示控制台（方便调试），`False`=不显示（窗口应用） |
| `exclude_binaries` | 是否排除二进制文件 | `True` | `True`=用于onedir模式，二进制文件单独收集 |
| `name` | 可执行文件名称 | `'main'` | 生成的exe文件名 |
| `debug` | 是否包含调试信息 | `False` | `True`=包含调试信息 |
| `upx` | 是否使用UPX压缩 | `True` | 可减小exe体积，需要安装UPX工具 |
| `strip` | 是否去除符号信息 | `False` | 可减小体积 |

**console 配置说明**:
- `True`: 显示控制台窗口，可以看到所有print输出，方便调试
- `False`: 不显示控制台，适合最终发布版本

**exclude_binaries 配置说明**:
- `True`: 用于onedir模式（目录模式），二进制文件会单独收集，不打包进exe
- `False`: 用于onefile模式（单文件模式），所有文件打包进一个exe

### 3.5 COLLECT 配置详解

**作用**: 收集所有文件到一个目录（onedir模式）

**关键配置项**:
- `exe`: 可执行文件
- `a.binaries`: 二进制文件
- `a.datas`: 数据文件
- `name`: 输出目录名称

**说明**: COLLECT用于onedir模式，将所有文件收集到一个目录中。

### 3.6 打包模式

#### 3.6.1 onedir模式（目录模式，当前使用）

**特点**:
- 生成一个目录，包含exe和所有依赖文件
- 启动速度较快
- 文件较大但易于调试

**适用场景**: 开发测试、需要频繁更新的场景

#### 3.6.2 onefile模式（单文件模式）

**如何改为onefile模式**:
```python
exe = EXE(
    pyz,
    a.scripts,
    a.binaries,      # 不排除二进制文件
    a.datas,         # 包含数据文件
    exclude_binaries=False,  # 改为False
    name='main',
    console=True,
    # ... 其他配置
)
# 删除COLLECT部分
```

**特点**:
- 生成单个exe文件
- 启动时需要解压，速度较慢
- 文件体积较大

**适用场景**: 最终发布版本

### 3.7 打包命令

```bash
# 1. 激活虚拟环境
venv\Scripts\activate.bat

# 2. 执行打包
pyinstaller main.spec
```

**打包输出**: `dist/main/` 目录

### 3.8 常见问题

#### Q1: 打包后exe无法运行

**可能原因**:
- 缺少依赖文件
- 路径问题
- 缺少隐藏导入

**解决方法**:
1. 检查 `dist/main/` 目录下所有文件是否完整
2. 检查 `hiddenimports` 是否包含所有必需的模块
3. 检查 `datas` 是否包含所有数据文件
4. 查看控制台错误信息（如果`console=True`）

#### Q2: 打包后体积过大

**解决方法**:
1. 使用 `excludes` 排除不需要的模块
2. 启用 `upx` 压缩
3. 启用 `strip` 去除符号信息
4. 使用 `optimize` 优化级别

#### Q3: 打包后找不到模板或静态文件

**解决方法**:
1. 检查 `datas` 配置是否正确
2. 检查代码中的路径处理逻辑（`sys.frozen`判断）
3. 确保打包后的目录结构与代码中的路径匹配

**相关文档**: 详细说明请参考 [开发指南.md](开发指南.md#5-打包配置详解)

## 5. Socket.IO 客户端配置

对接 `docs/websocket-api.md`：服务端为 Socket.IO，path `/ws`，默认事件 `forward`。

### 5.1 配置项（src/config.py）

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `WS_CLIENT_ENABLED` | bool | `True` | 是否启用，Flask 启动时自动连接 |
| `WS_CLIENT_HOST` | str | `'127.0.0.1'` | 服务端地址，测试环境为 localhost |
